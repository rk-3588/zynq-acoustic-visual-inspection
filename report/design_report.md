# 基于Zynq的便携式声源可视化与视觉辅助检测系统

本文介绍系统架构、核心算法与软硬件实现。完整图文说明见 [设计报告](design_report_v1.docx)，直接运行见 [复现说明](../reproduce/README.md)。

## 1. 背景与目标

设备或产品的声音能够反映运行状态，但人耳难以在复杂场景中稳定指认发声部位。声学相机将阵列测量的空间能量分布叠加到真实图像，可帮助使用者快速缩小观察范围。本设计以Zynq-7020为核心，把声源定位、视觉辅助处理、触摸测量记录和外部执行器区域控制整合为便携样机。

最初设想中的“声视融合异常检测与自主复检”是应用方向。当前交付的实际能力是声源可视化、像素级视觉辅助和区域动作接口，没有把声音ACTIVE当作故障类别识别，也没有实现三维抓取位姿估计或抵近后自动复测判定的完整闭环。

基础声学相机参考 `wzwyz/ZYNQ-based-acoustic-camera`。原工程的麦克风接收、延时求和及声视叠加属于继承基础；本次主要工作是阵列/器件适配、Linux迁移、信号与显示稳定化、UIO测量接口、交互和外部控制联动。第三方来源与许可范围见 [许可说明](../license_scope.md)。

## 2. 总体架构与划分

时序敏感、持续吞吐的处理放在PL：16麦接收、200 Hz高通、样本缓存、分数延迟、求和能量、热点提取、摄像头采集、六模式像素处理、伪彩色与界面合成。Linux承担状态采样、门控和色阶策略、单通道频率估算、触摸UI、SD记录及机械臂任务协议。

这种划分避免Linux逐帧搬运整路摄像头来实现实时显示。UI由Linux写入两块RGBA DDR缓冲，由Mixer读取合成；相机、声学图层仍沿PL视频通路运行。UI刷新频率与HDMI扫描频率是两种不同负载。

系统框图见完整设计报告。关键互连包括PS AXI GP控制、HP0 DDR访问、通用UIO寄存器映射、USB触摸和UART1外部控制器接口。硬件器件为XC7Z020-CLG400-2，工具为2026.1，内存根文件系统为SD第二分区EXT4。

## 3. 声学阵列与算法

阵列使用16个ICS-43434，内环半径25 mm、外环50 mm。两环物理编号起点不同：data0～7依次对应内环SE、S、SW、W、NW、N、NE、E；data8～15依次对应外环E、NE、N、NW、W、SW、S、SE。最终连线以确认后的XDC和阵列几何表为准，不能根据插针图片的相邻文字重新推定引脚。

ICS-43434的LR接地，接收器按左声道对齐，保留I2S的一位延迟后采集signed24数据。当前配置产生3 MHz SCK、46.875 kHz WS，16路数据一起提交至声学流水线。

内部扫描网格为64×36。方向模型采用远场方向延迟，依据麦克风坐标、采样率、343 m/s声速及60°对角视场假设生成Q5延迟。视场假设不是镜头标定结果。相对公共最小延迟分解为缓存地址和两点插值权重，再对齐求和并计算能量。

外环必须先在**有符号几何延迟**上进行方位反序和半径比2的变换，再求公共最小值；把最终RAM地址直接翻倍会破坏延迟含义。`delay`保留11级调度约定，II=1，独立整数参考覆盖全部16通道、边界地址和回卷。ROM物理深度9216，前2304项有效，其余为0。

200 Hz高通在PL前置，改善静音背景和弱声稳定性；用户曾确认低音量及约1米测试更稳定。该反馈是特定场景的功能观察，不是统一条件下的SNR或最大探测距离测量。低频受阵列孔径限制，热点较宽；较高频率对反射和安装条件敏感，脱离桌面后双热点现象明显改善。

Linux进一步加入静音门限与滞回、动态色阶及时间平滑。定位服务通过状态源新鲜度、合法坐标、窗口中位数和空间聚集/驻留判断提供实时与稳定坐标；它不是概率置信度，也不能凭软件读取证明所有寄存器严格同帧。

## 4. 视觉链路与界面

OV5640输出经RGB565采集与RGB888转换、Video In和摄像头VDMA进入DDR，再由MM2S送入视频预处理。预处理提供原图、灰度、二值化、亮度偏移、反相、移位增益，并支持全屏、手动矩形及声源稳定坐标跟随ROI。框外保留原图，配置在接受的帧首应用，提供区域面积和亮像素占比统计。

摄像头结果与声学伪彩色由add_image叠加，再进入Video Mixer与Linux UI合成，最后经Video Out、时序和TMDS输出HDMI。预处理位于叠加之前，因此灰度或二值化不会改变热图和UI颜色。

UI为自编C/RGBA实现，并未采用Qt或LVGL。顶部保留阵列、算法模式、声音状态、温度和运行时间；可收起半透明侧栏显示实时/稳定坐标、能量、频率及机械臂状态。底栏含声学开关、模式/区域抽屉、抓拍、执行、相册和设置。

UI双缓冲位于0x03000000与0x03400000，均在预留no-map DDR内。写入空闲槽后发布地址，按两个新的完成事件退役旧槽；寄存器地址读回不等于硬件已读完缓冲。正常退出排空Mixer并恢复主层，不在失败时擅自强杀或硬复位视频。

最终摄像头保留降频配置0x3035=0x21，最后一次0x3821=0x01实现当前水平翻转。PL同时将热图列和热点横坐标翻转，避免只翻相机造成方向错配。几何、声学求和及通道物理接线不变。

## 5. 测量、记录与执行接口

单麦频率使用CH0高通后2048点冻结快照，在Linux完成去均值、Hann窗及FFT。它提供该通道的主峰候选，不声称频率属于画面某个热点。2 kHz测试音可正常显示；频率读数表示CH0输入的主峰。

抓拍保存1280×720摄像头原图BMP和同次软件请求的测量JSON，另有160×90缩略图。相册详情显示640×360预览和文本测量摘要。记录包含坐标、门控、频率、温度及有效性，不是最终HDMI截图，也不保证相机、定位和频率硬件严格同帧。

机械臂有独立主控，通过UART区域任务联动。手动夹取使用最新有效实时坐标三等分区域；确认弹窗随实时目标更新，暂时失效时禁用确认而不立即关闭。服务收到请求后重新取实时区域，使用任务号、持久状态和nonce避免重复动作。自动夹取和跟踪仍保留稳定目标与驻留约束。UI状态与串口打开成功不能证明机械连接或夹持成功。

历史串口长回包受驱动FIFO批量交付影响：130字节响应以56/56/18字节交付时出现约59ms的主机间隔。将主机半包等待与请求总期限分开处理后，保持协议和任务有效性检查。该经验提炼为可复用技能包，并有Python/C前后对照和30项离线验证。

## 6. 工程问题与优化判断

| 问题与观察 | 更改和依据 | 已得到的结果 / 边界 |
| --- | --- | --- |
| 小孔径阵列在低采样率下热点偏中心 | 采用46.875 kHz并把扫描网格降为64×36，保留算力裕量 | 热点跟随获确认；不将更粗网格称为物理分辨率提高 |
| 静音背景大、弱声不稳 | 200 Hz高通＋静音门控＋动态色阶平滑 | 静音闪色消失，弱声显示稳定性改善 |
| Linux视频启动与裸机不一致 | 对照GPIO/SCCB、VDMA几何与触发顺序、VTC寄存器和真实板端状态 | 逐层恢复；不把所有问题笼统归于Linux |
| 30 cm DVP接线出现像素噪点/帧错误 | PCLK/GND配对有改善，保留摄像头分频加倍的对照配置 | 采集无错、抓拍可用；同时降低信号速率和DDR负载，不能仅此证明唯一根因 |
| UI全帧物理读回开销 | 全帧验证移到图层启用前，正常刷新使用屏障与双缓冲退役 | 代表性循环约233ms降至约125ms；属于CPU显示循环，不是相机帧率 |
| 相册等操作后整屏竖纹 | 采集仍无错，UI开启时SOF约80/s；关UI→60/s并恢复 | 收窄到公共显示通路，欠流/同步根因未直接证实 |
| 固定开机重开UI不能覆盖运行期故障 | 独立看门狗按连续3区间与VDMA条件恢复，10秒冷却 | 用户实测自动恢复成功；不是所有黑屏的通用检测 |

## 7. 验证与实现数据

冻结bit的最终实现报告：LUT 25603/53200，FF 46470/106400，BRAM 129/140，DSP 133/220，WNS +0.136ns、WHS +0.036ns，TNS/THS均为0，布线错误0。BRAM占用92.14%，不能仅凭LUT尚有余量判断还能任意增加行缓存或算法。

独立源码目录完成12个Linux程序编译及软件回归，包括FFT、2000组USB PHY模拟、手动实时区域、真实UI tick、UI生命周期、独立看门狗模拟UIO、PTY协议与技能包Python/C对照。Vivado从独立目录完成工程创建、BD校验与输出生成；RTL模块仿真及文件完整性检查结果见 [测试与验证](verification.md)。
